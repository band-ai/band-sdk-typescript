# 1.0 platform tool + MCP rename (Thenvoi -> Band)

> **Release-notes item for the tool/MCP surface.** This is a clean 1.0
> compatibility break: the SDK advertises and accepts Band tool names only. It
> does not normalize or dual-register legacy `thenvoi_*` calls, and an old MCP
> host allowlist exposes no renamed tools. The SDK cannot repair a capability a
> host never sends it.

## What changed

- The 17 platform tools are advertised and accepted only as `band_<operation>`
  (was `thenvoi_<operation>`). Tool arguments, result schemas, capability
  policy, handler behavior, and group membership (chat 7 / contact 5 / memory 5)
  are unchanged.
- MCP-qualified tool names are `mcp__band__band_<operation>` (was
  `mcp__thenvoi__thenvoi_<operation>`); `MCP_TOOL_PREFIX = "mcp__band__"`.
- One exported `MCP_SERVER_NAME = "band"` owns every MCP/ACP/OpenCode/Claude
  server-name default and the Claude `mcpServers` key; no `"thenvoi"` server
  literal remains.
- A raw legacy `thenvoi_*` name that reaches the SDK follows the existing
  unknown-tool path (`ToolNotFoundError`); registration-based adapters never
  expose it. There is no legacy alias or dual registration.

## Upgrade order (do these in sequence)

1. **Change MCP host allowlists** from `mcp__thenvoi__*` to `mcp__band__*`. An
   old allowlist exposes none of the renamed tools; dual-registering both
   prefixes does not fix a host policy that allows only the old server.
2. **Update the explicit MCP server name** from `thenvoi` to `band` wherever it
   is configured (host config, editor MCP entries).
3. **Update prompts and saved tool-call examples** from `thenvoi_*` to
   `band_*`. These are upgrade prerequisites, not temporarily compatible inputs.
4. **Deploy SDK 1.0.0.**

## Not changed (retained by design)

The Linear bridge observability event names (`linear_thenvoi_bridge.*`), the
persisted SQLite physical identifiers (`linear_thenvoi_session_rooms`,
`linear_thenvoi_bootstrap_requests`, `thenvoi_room_id`), the
`.linear-thenvoi-example.sqlite` default filename, wire DTO/event fields, and
the legacy `THENVOI_*` environment fallback remain as-is (the
`LINEAR_THENVOI_*` Linear-bridge fallback was removed in INT-1343).

The package publication remains on hold (`.release-hold`) until the rename PR is
approved and merged.
