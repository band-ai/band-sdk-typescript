# 1.0 agents rejoin their existing rooms by default

> **Breaking runtime default.** It changes which rooms an agent listens to
> without a compile error or warning.

## What changed

`AgentConfig.autoSubscribeExistingRooms` now defaults to `true`. Before 1.0 it
defaulted to `false`.

- **0.x:** an agent created without `agentConfig` joined only rooms it was added
  to while running. After a restart it ignored every room it already belonged
  to until someone removed and re-added it.
- **1.0:** at startup and after a whole-agent reconnect, the agent lists the
  rooms it already belongs to and joins them, subject to `roomFilter`. It then
  catches up on unprocessed messages there, like any other room it joins.

The Python SDK already defaults to `True`, so both SDKs now behave the same.

## Who is affected

Agents that never set `autoSubscribeExistingRooms`. On their first 1.0 start
they join every room they already belong to and may answer pending messages
there. Agents that already set `true` are unaffected, and that setting is now
redundant.

## Keep the 0.x behavior

To join only rooms the agent is added to while running, opt out explicitly:

```ts
const agent = Agent.create({
  adapter,
  config,
  agentConfig: { autoSubscribeExistingRooms: false },
});
```

To join only some existing rooms, keep the default and pass a `roomFilter`.
